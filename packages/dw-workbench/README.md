# DW-Workbench 0.4.1

PortableのDocuWorks項目確認アプリ。操作説明は[WORKBENCH_JA.md](../../docs/WORKBENCH_JA.md)。
v0.2.0はv0.1.0の`bb069cf3fb290df868da53fe947c9a7844f0e098`から独立した開発場所で作成しました。
旧アプリ・旧Portableと並存する独立パッケージです。
v0.3.0の[複数文書への一括テンプレート適用](../../docs/BULK_TEMPLATE_JA.md)を維持し、v0.4.0では[操作導線](../../docs/WORKFLOW_UI_JA.md)・[台帳照合と注釈](../../docs/LEDGER_MARKUP_JA.md)を追加しています。

## 責任と保存

- `domain.py`: 原本スナップショット、mm座標の根拠、項目定義、文書用・ページ用テンプレート、ページ割当、観測、候補、採用値、確認規則、十進値。
- `application.py`: 原本登録、処理単位、ページ割当と履歴、訂正、版照合、候補取込、確認、確定、ジョブ完了の保存。
- `storage.py`: SQLite、OSロック、相対パス、原本ハッシュ、トランザクション、Backup API、旧案件のコピー移行。
- `library.py`: Portable内の共通テンプレートと項目定義の不変な登録版。案件への取り込みは完全なスナップショットです。
- `workers.py`: 読み取り専用Core接続と公開GPU OCR接続。各一つのローカルプロセス。DBを開きません。
- `exporting.py`: 固定したデータからXLSX／CSVを生成し、独立したXML／CSV読取で値と型を検証します。
- `ui.py`: Tkメインスレッドで画面・DB更新。コピー・描画・OCR・出力・バックアップのファイル処理は画面から分離します。

DB保存形式は`PRAGMA user_version=2`。原本、項目定義、設定版、観測、候補、確定結果は追記し、更新をDBトリガーでも拒否します。
一つのXDWの処理単位は文書またはページです。適用後の処理単位変更は一括適用プレビューで既存記録の置換を確認します。旧記録と確定結果を保持し、新しい採用欄は未入力にします。
ページ用テンプレートの範囲は相対ページ1で保存し、適用先の実ページへ変換します。
同じ項目定義ID・版を明示的に共有したテンプレートだけを同じ出力表へまとめます。
テンプレートの変更は旧記録を閲覧専用で保持し、新記録の採用欄を空にします。同じ版の適用は変更しません。
記録ごとの`revision`が採用値・確認状態の版です。更新には`expected_revision`を渡します。
ページ割当にも独立した版を持ち、一括操作の古い版は全体を拒否します。
再OCRで観測・候補を追加しても採用値・確認状態・人の編集版は変わりません。
遅れて到着した変更前のOCR結果は現在の記録へ保存しません。
根拠は固定原本ID・SHA256・1始まりのページ番号・`(x,y,width,height)`mmです。
画面倍率と切り抜き画素座標は根拠の座標と分離します。
原本の全体ハッシュ検査は画面の外で実行し、DB更新前にファイルID・サイズ・更新時刻を照合します。
検査中の確認・確定操作では編集を停止し、検査後に原本が変わっていた場合は結果を拒否します。

ジョブは`pending → running → complete / failed`です。テンプレート切替で旧OCRは`cancelled`になります。
異常終了後の`running`は次回開始時に`pending`へ戻します。
完了した観測とジョブ状態は同じトランザクションで保存するため、再開で候補が重複しません。
生成済み画像にはハッシュを持たせ、破損・削除時は描画から再開します。
保存失敗時は編集入力とワーカー結果を画面内に保持し、保存の再試行を可能にします。

バックアップはDBスナップショットを先に作り、固定原本・出力・未登録草案をコピーしてマニフェストを作成します。
コピー完了まで`INCOMPLETE.txt`を保持し、この印がある案件は開きません。
キャッシュはバックアップ対象外です。復元時に固定原本から再描画できます。
旧形式1の案件を直接書き換えません。ロックとBackup APIで別コピーへ移行し、旧記録ID・採用値・候補・確定結果JSONを保持します。
旧確定結果の再出力は旧ファイル形式です。新規確定結果は形式2の案件一括XLSXと表別CSVです。

## 出力契約

一回の確定結果は不変です。形式2は`exports/<確定結果ID>/案件結果.xlsx`を一つ生成します。
項目定義ID・版ごとの`結果01`等に加え、共有の`根拠`と`出力情報`シートを持ちます。
行順は原本登録順、実ページ順です。文書単位の元ページ番号は空欄です。
CSVは同じフォルダーへ結果表ごとにUTF-8 BOM付きで生成します。
`staging`で生成し、ZIP/XML・CSVを独立に読み取って値と型を検証してから公開します。
再試行では成功済みファイルを検証し、失敗・未生成・破損したファイルだけを生成します。

## 開発・検証

外部DocuWorksとGPUドライバーを除く実行環境は固定済みPortableを使います。
`scripts/build_workbench.py`は基準ZIPまたは基準Portableの同梱マニフェストを確認し、固定したvendorファイルをSHA256で検証して別候補を作成します。
`scripts/update_workbench.py`は同じ版の候補内の新アプリだけを更新します。旧版への上書きを拒否します。
`BUILD.json`へwheelハッシュと利用可能なGitのソース版・未コミット変更の有無を記録します。

```powershell
& '<Portable>\runtime\python.exe' -I -B -X utf8 -m pytest -q -p no:cacheprovider packages\dw-workbench\tests
& '<Portable>\runtime\python.exe' -I -B -X utf8 scripts\verify_workbench_v020.py --portable '<Portable>' --evidence '<証跡>'
& '<Portable>\runtime\python.exe' -I -B -X utf8 scripts\verify_workbench_v020_portable.py --portable '<Portable>' --evidence '<移動証跡>' --vendor
& '<Portable>\runtime\python.exe' -I -B -X utf8 scripts\verify_workbench_v020_migration.py --old-portable '<旧Portable>' --portable '<Portable>' --evidence '<移行証跡>'
```

試験用フォルダーは通常の`mkdir`でACLを継承します。Pythonの0700一時フォルダーをこのWindows環境では使用しません。
自動試験は合成XDWを使います。現地帳票、手動の画面・Viewer確認、9.1互換性は別の受け入れ確認です。
通常負荷の既定値は100文書×10ページ×30項目／ページです。実SDK描画1,000ページと実GPU OCR30,000範囲を実行し、結果・根拠・出力・再開・メモリを記録します。
Portable検証は元の負荷案件を読み取り専用で複製し、相対参照、型付き出力再試行、共通登録、復元、GPU無効化、Tk操作、二重起動を確認します。
Portable全体のC／E移動は別途実行し、移動先で同じ検証器を使います。旧v0.1.0用検証スクリプトは履歴として残します。
開発ソースと実行候補に実帳票を含めず、公開・ライセンス変更・タグ作成はこの作業で実行しません。

v0.4.1候補では寸法不一致スキップ、未操作欄へのOCR自動入力、確認して次へを追加します。自動入力は未確認で、手編集・意図的な空欄化・確認済みを保護します。
