# 白紙Review生成の軽量化（v0.4.1）

以下は軽量化単独候補（Integrations 0.8.1 / Core 1.0.0）の測定記録です。現行候補はCore 1.0.1を組み合わせています。テキスト背景を塗りつぶしなしにし、新規白紙Review生成中のページ情報取得と追加アノテーション探索を削減しました。

## 実測

Windows x64 / Python 3.13.15 / DocuWorks API 10.1.1。A4の合成文字列で、変更前後とも背景なしです。
各5回、別プロセス・別出力で交互に実行した生成時間の中央値です。OCR実行時間やSession全体の所要時間ではありません。

|配置|変更前|変更後|
|---|---:|---:|
|1ページ10個|2.541秒|0.439秒|
|1ページ25個|28.291秒|0.873秒|
|5ページ各5個|2.906秒|0.960秒|

25個の診断ではページ情報取得25回→1回、アノテーション情報取得325回→25回。属性書き込み175回と保存1回は同数です。
大きな割合を占めていたのは追加ごとのページ情報取得でした。
候補のみの合成試験（各3回中央値）は100個2.928秒、500個14.150秒、1000個28.756秒。
100個の旧処理は45秒で打ち切ったため、大量データでの速度比は算出していません。
500/1000個は一部座標が重なる負荷試験であり、実文書やViewer操作の速度を表すものではありません。

## 正しさと適用範囲

### Core 1.0.1を組み合わせた再計測

軽量化済みCore 1.0.0候補と、Core 1.0.1候補を同じ環境で各5回交互に測定しました。
これは軽量化前との速度比ではなく、安全性修正による性能低下がないかを確認する比較です。
保存後の文字・位置・サイズ・識別属性は全50試行で条件ごとに一致しました。

|配置|Core 1.0.0候補|Core 1.0.1候補|
|---|---:|---:|
|1ページ100個|3.118秒|3.076秒|
|1ページ500個|14.663秒|15.348秒|
|1ページ1000個|28.779秒|28.308秒|
|10ページ各100個|29.157秒|29.379秒|
|A4・白紙・A3混在、24個|1.145秒|1.179秒|

生成処理だけの中央値です。保存後検査、OCRエンジン、Viewer操作の時間は含みません。
500/1000個の1ページ試験は座標が重なる合成負荷です。10ページ分散試験も合成データであり、実文書の確認とは区別します。

### 保存結果と互換性

- 追加APIの返すハンドルと予想位置を毎回照合。想定外は従来探索へ戻し、そのページの最適化を無効にします。
- SDKから得た位置・サイズを使用し、保存後の全検査と識別属性を維持します。
- 小規模5条件で旧処理と保存後の全スナップショット一致、4ページでSDK画像出力の画素一致を確認しました。
- 実DLLへの障害応答注入でフォールバック、元エラー保持、不完全なSessionを残さないことを確認しました。
- Python 3.10の探索単体試験、DocuWorks 10.1.1の保存・再読込・取り込みを検証しています。
- DocuWorks 9.1実機、実文書の高密度OCR、Viewerの大量文字操作は未確認です。
- 軽量化単独の測定時点ではCoreの3課題は対象外でした。現行候補の修正内容と残る確認は[Core 1.0.1課題対応台帳](maintainer/CORE_1.0.1_ISSUES.md)を参照してください。
