# 白紙ReviewのViewer確認手順

生成・取り込み・保存後照合は開発担当が行います。Viewerの操作ではPythonやBATを実行する必要はありません。
この手順は目視確認用です。SDKによる代替実行の結果と、Viewerで人間が確認した結果は別に記録します。

## 準備

開発担当は `scripts/reviewed_dev.py fixture` で生成した1ページXDWからSessionを作り、利用者に `review.xdw` の場所を案内します。
文字は上から「部品番号」「部品番号」「削除対象」です。原本 `initial.xdw` とSessionのJSONは編集しません。
複数ページはA4印字、A4白紙、A3横印字の3ページを使います。
各ケースに独立した初期XDWコピーを用意し、保存先を明記します。

## 最初の確認：1ページ基本編集

1. `review.xdw` を開き、白紙に赤い12pt文字3個があり、警告がないことを確認する。
2. 一番上を「部品番号A-001」に修正して右へ移動する。
3. 真ん中の文字は残し、一番下の「削除対象」は削除する。
4. ページへ直接、黒文字「追加確認」を追加する。
5. 指定された作業コピーへ保存して閉じ、同じファイルを開き直す。
6. 文字化け・修復警告がないこと、文字と配置が保持されていること、再編集できることを確認して閉じる。

担当者は保存済みXDWを取り込み、文字3個が期待どおりであり、最初の文字が移動し、削除文字がなく、新規文字が取り込まれたことを確認する。
SDKで別途読み出した文字・位置・サイズ・方向とReviewedを照合する。

## 次のケース

| ケース | Viewer操作 | 期待する取り込み結果 |
|---|---|---|
| 02 コピー | 一番上をコピーし、コピー側を「コピー確認」にする | 4個保持。コピーされた来歴を重複として扱う |
| 03 表示属性 | 上を30度回転、中央を縦書き、下を「折り返し確認の長い文字列」にし、折り返し枠を狭くする | 回転・書字方向とSDK実測枠が一致する |
| 04 空ページ | 3ページ文書の2ページ目に「空ページ追加」を直接貼る | 2ページ目にも文字がある。3ページを保持 |
| 05 全削除 | 1ページ文書の文字3個をすべて削除する | 1ページ・文字0件。削除したページと区別する |
| 06 複数ページ | 1ページ目の上を「A4確認」、3ページ目の上を「A3確認」にする | A4・白紙A4・A3横のページ対応と文字が一致 |
| 07 グループ | 上と中央の文字をグループ化 | 未対応構造として全体拒否。結果フォルダーなし |
| 08 付箋 | 付箋の中へ「付箋内確認」のテキストを貼る | 未対応構造として全体拒否。結果フォルダーなし |
| 09 ページ構成 | 3ページ文書の2ページ目を削除 | ページ数不一致で全体拒否。結果フォルダーなし |

正常ケース02～06も保存後に開き直して、警告・文字化け・変更維持・再編集を確認します。
SDK自動試験ではさらに、実際のページ入替え、ページ追加、180度回転、識別属性の欠落・破損も扱います。

## 記録

操作担当（人間／SDK）、使用アプリ・APIの版、入力・出力ハッシュ、期待する操作、取得した文字と実測枠、拒否理由、結果確定の有無を残します。
Viewerを使っていないSDK実行を「Viewer確認済み」としません。
この開発版の実施結果は [検証記録](REVIEWED_RESULT_VERIFICATION.md) を参照してください。
