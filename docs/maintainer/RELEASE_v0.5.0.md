2026-09-22時点の配布構成と検証方針です。機能基準は公開mainのecf32e6で、
取り込み2.0・矩形テンプレート・CSV出力・矩形生成の速度改善を含みます。
最終成果物の試験結果・対象コミット・ハッシュはReleaseに添付するVERIFICATION_JA.mdと
RELEASE_PROVENANCE.jsonを正とします。本書の受け入れ項目だけで検証済みとは扱いません。

## 更新内容

- Reviewed取り込みをID照合中心で利用し、複数origin、参照なし、不正な参照の診断を保持する。付箋メモを本文から除外する。
- 1つのXDWに置いた複数矩形へ項目名・適用条件・出力順を設定し、テンプレートとして登録する。
- 校正後の文字・位置から項目を取得し、値・参照元・診断をStructured Resultへ保存する。
- 同じ登録テンプレートの結果を、UTF-8 BOM付き・1文書1レコードのCSVへまとめる。
- 矩形生成時のページ情報の再取得を減らし、既存の矩形属性・保存後の結果を維持する。

対象の流れは「OCR → Viewer修正 → Reviewed → テンプレート適用 → Structured → CSV」です。
XLSX、取得結果に基づく原本コピーへのマーカー、繰り返し明細、自動テンプレート選択、
位置補正、専用GUIは含めません。既存のOCR領域を対象にしたマーカーAPIとは区別します。

## 利用方法と互換性

OCR開始.batと校正結果取込.batを維持します。テンプレート登録・確認・適用とCSV出力には
既存のdocuworks-integrations.batを使用します。専用BATの追加は今回行いません。
[利用手順](../user/README.md)と[テンプレートからCSVまで](../user/template-csv.md)を公開物へ含めます。

新しいPortableを別フォルダーへ展開し、旧版・元文書・保存結果を保持します。
既存Reviewed 1.0と新2.0を読み込めますが、新形式の結果を旧版で利用できるとは扱いません。
テンプレートはReviewed座標へ適用し、Canonicalの原本座標は変更しません。
同じテンプレート名でも再登録した定義は別版となり、CSVへ混在できません。
ページ追加・削除・並べ替え・寸法変更・ページ回転は取り込み仕様の対象外です。

## 候補の組み立て方

1. 準備変更を含むソースのコミットとsource-manifestを固定する。
2. v0.4.1の公開ソースZIP・Core配布物・第三者通知を公開ReleaseのSHA-256と照合する。
   廃棄済みの古い候補や試験後のインストール先を基準にしない。
3. export_public_source.pyへ`--release-version v0.5.0`を明示し、新規フォルダーへ公開候補を生成する。
   自作部分は既存MIT条件へ変換し、第三者通知を保持する。
4. Integrationsの公開用sdistを作り、新規展開先からwheelを作る。Core 1.0.1の公開済み配布物を使用する。
   公開用ソース・wheel・導入後の機能本体を照合し、監査・独立導入・未加工sdist試験を行う。
5. 公開v0.4.1の復元Portableを基準に、build_portable_candidate.pyへ基準SHA-256、公開wheel、
   公開候補のportableとsource、`--release-version v0.5.0`、新規出力先を指定する。
   基準復元ZIPのSHA-256は`fc1ea11eab639d737563ed0d70623682f39913cf11e0ec29e7ed413597f7fa57`。
6. 最終Portableを検証後、分割ZIP・結合ツール・公開ソース・wheel/sdist・通知・検証報告を凍結する。
   ファイル名・サイズ・SHA-256を記録し、公開対象だけの一覧を作る。
