# 工程に沿ったWorkbench UI：ローカル検証記録

2026年10月5日。起点は `c5f70b9`、専用ブランチ `feat/local-review-navigation-20261005`。開始時の作業コピーに未コミット変更はありませんでした。既存Portable・公開側の変更・稼働中Workbenchには書き込まず、独立した `ui-demo` で実装・合成試験を行いました。

## 問題と変更

改善前の実画面では、登録・中断・バックアップが横並びで、読取設定画面に範囲作成・OCR・Excel出力が混在していました。1000×650の確認画面では主操作がスクロール下へ隠れ、台帳照合の入口は履歴にありました。

上部を6工程の入口、現在の画面・未完了件数、状態に合う次の操作、無効理由に整理しました。入口は画面移動で、実行や確認済みを自動で進めません。文書・範囲・確認・出力・履歴・共通のタブで戻り・一括作業・途中再開を保ちます。管理・復旧を主導線から分けてアクセスを残しました。

確認画面の確認・次の未完了・出力への主ボタンを固定しました。新しい出力画面で確定／Excelと台帳照合を選べます。台帳画面は条件設定と原文確認に分け、条件変更で再プレビューを求め、注釈出力ボタンと無効理由を固定しました。

入力保存、原文との照合による確認済み、その時点の値と根拠の確定、ファイル生成の出力を明示します。台帳の原本位置は内部ID・ハッシュの列挙から実ページとmm範囲へ変えました。DB・ID・原本座標・確定結果・SDK契約・保存形式は変更していません。

## 主なファイル

- `dw_workbench/ui_guidance.py`：表示・工程移動・ボタンの状態／理由・キーボード・スクロール。業務判定は既存の完了規則を参照。
- `dw_workbench/ui.py`：工程別配置、固定主操作、出力画面、短いタブ名、管理メニュー、案内文言。
- `dw_workbench/ledger_ui.py`：条件→プレビューの配置、固定出力、戻る・無効理由・原本位置の表示。
- `tests/test_workflow_ui.py`：新規・再開・取消・入力未選択・OCR候補生成・保存失敗・連打・キーボード・狭い／文字拡大・台帳経路の5つの実Tk試験。
- `tests/test_v020_ui.py`：既存のGUI隔離実行を、呼出元の試験ファイルでも利用可能にした変更。
- `docs/WORKFLOW_UI_JA.md`、既存Workbench／台帳手順：現在の文言と導線へ同期。

未完了案内の初期集計は案件の現在記録を参照し、項目保存時は表示中の記録だけを更新します。新しい不変な確定結果はrowidによる追加分だけを読みます。既存の「項目保存・OCR候補更新で他の文書を再走査しない」回帰を維持しました。

## 検証と境界

Workbench全体 **149件成功**。新規・取消・再開、適用前の戻る、候補生成が確認状態を変えないこと、保存失敗時の入力・表示位置保持、再保存、Ctrl+S／Ctrl+Enter／Alt移動、実行中の二重確認防止、1000×650の固定ボタン、文字拡大、フォーカス／PageDownスクロール、出力から台帳を開く経路を確認しました。既存のキャンセル・保存再開・注釈失敗・入力変更の回帰も継続しています。

通常起動から出力画面の入口で台帳照合を開き、保存した条件・除外5件を再開、原本切り抜きを表示、実SDKで2文書・2箇所へ注釈出力を確認しました。二重クリックの出力は1回でした。業務ロジック・SDKライターはこのUI変更では変更していません。

Windows PrintWindowで、対象の合成アプリの改善前3画面と改善後の文書・確認・出力・履歴・台帳条件・原文プレビュー・文字拡大・出力完了画面を取得しました。PNGを実際に読み、主操作の配置と折返し・スクロールを確認しています。旧作業で失敗した全画面のImageGrabとは別に、今回のウィンドウ単位の実画面取得が成功しました。合成データの画面は認識精度の検証ではありません。

専用BATの起動チェック、ソース監査、AST、差分空白、ローカルwheelのCRC・全14モジュールのソース一致も確認しました。型チェッカーは環境にないため未実施です。既存の配布一覧不一致11件は起点より前からある問題で、UI変更とは分けて記録します。

Viewer目視、実帳票、DocuWorks 9.1、全Windows DPI／全モニター、更新済みPortable一式の移動は未確認です。OCRはUIの候補生成経路と既存回帰を確認し、この独立モデルなし環境で実GPU認識を再試験したものではありません。

既存のWorkbench 2プロセスを終了していません。push、PR、merge、Release、配布、外部送信は行っていません。次の公開工程はUI差分のレビュー、既存の配布一覧問題の解決、別Portableの組立・移動確認、現地とViewerの受け入れです。
