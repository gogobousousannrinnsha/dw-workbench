## 実SDK・実GPU OCR

Python 3.13.15、インストール済みDocuWorks SDK API 10.1.1を使用しました。
既存のPython 3.13 GPU実行環境と固定 `PP-OCRv6_medium_det` / `PP-OCRv6_medium_rec` を使い、キャッシュは専用作業領域へ保存しました。
モデルファイルの現在のハッシュはOCR記録内のハッシュと一致しています。

| 生成した実XDW | 実OCR結果 | Review→Reviewed→JSONL |
|---|---|---|
| 日本語印字A4、白紙A4、日本語印字A3横 | ページ別文字数 3 / 0 / 3 | 3ページ・6文字を保持 |
| 全ページ白紙の2ページ | 0 / 0 | 2ページ・0文字、空JSONL |

ソース実行と新規wheel読み込みの両方で実OCRを実施しました。合成Canonicalへの置換はありません。
最終wheelでは文書リンクだけを調整しており、GPU検証時のwheelとパッケージ内45ファイル（実装・Schema・仕様）のバイト列が一致します。
ここで確認したのは、実OCR出力からの接続と校正データの保存です。一般文書に対するOCR精度の評価ではありません。

実SDK試験は、文字修正・追加・削除・全削除・移動・コピー相当の来歴複製、回転、縦書き、枠変更、来歴属性の欠落・破損・別Session、非テキスト追加、グループ・付箋、ページ追加・削除・実際の入替え・180度回転、文書／ページ属性の欠落を含みます。
取り込み成功時は、保存後のSDK実測文字・座標・寸法・方向とReviewedを一致照合しました。未対応構造やページ不整合では完成結果フォルダーが存在しません。
