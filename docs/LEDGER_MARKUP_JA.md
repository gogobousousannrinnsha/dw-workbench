# 台帳照合と注釈付きXDWのローカル試用

Workbenchで確認して確定した結果をExcel台帳と照合し、条件に合う項目の原本範囲へ塗りなしの矩形を追加したXDWコピーを作ります。台帳・固定原本・採用値は変更しません。

初版は.xlsxの1シート、1つの照合キー、1つの条件列と完全一致値、1つの描画項目に対応します。色は赤・青・緑・黄です。Excelのインストールや台帳読取用の追加パッケージは不要です。XDWの表示・出力にはDocuWorks SDKが必要です。

## 操作

1. 通常の確認・訂正を終え、「案件の確認済み結果をExcel／CSVへ出力」で結果を確定します。v0.2.0形式の確定結果が対象です。
2. 「出力」画面の「台帳を選び、照合プレビューへ進む」を押します。「履歴」からも開けます。
3. 確定結果と項目定義版を選び、台帳.xlsxを選択します。「シート読込」、対象シート、見出し行、「見出し読込」の順に指定します。
4. 「結果の照合項目」と「台帳の照合列」を指定します。例えば、両側の「部品番号」です。別に「枠を付ける項目」を指定します。例えば、「温度」の原文範囲です。
5. 「台帳の条件列」、条件値の型、完全一致する値、枠の色を指定します。例：文字列の「判定」が「対象」と一致。
6. 「この条件で照合してプレビューを保存」を押します。「原文と判定を確認」へ進み、記録の対象・対象外・要確認・明示除外件数と、台帳側の診断件数を確認します。
7. 行を選ぶと、原文切り抜き、原文表記、採用値、台帳値、理由、固定原本の実ページとmm範囲を確認できます。複数選択にはCtrl／Shiftキーを使います。
8. 要確認があれば、元データを訂正して再照合するか、対象を選択して「選択を理由付きで明示除外」を押します。理由なしの除外はできません。「選択の除外を戻す」で元の判断へ戻せます。
9. 要確認がなく、描画対象があると画面下の「原本コピーへ注釈付きXDWを出力」が有効になります。確認して実行すると、元文書ごとに新しいXDWコピーとreport.jsonを作ります。

条件・シート・見出し・項目を変えると再プレビューが必要です。既に保存した照合は残ります。訂正画面の採用値は照合画面では変更しません。訂正後の結果を使う場合は新しく確定してください。

## 照合規則

| 入力 | 扱い |
|---|---|
| 文字列の000123 | 先頭ゼロ・空白・全角半角をそのまま完全一致。123とは別 |
| 数値の123を000000書式で表示 | 数値123。表示書式から000123を復元しない |
| 数値比較 | 両側が数値で、利用者が「数値」を指定した場合のみ。25と25.0は一致 |
| 数式 | 保存済み計算結果を採用せず、要確認。外部参照も実行しない |
| 空欄・結合・エラー・真偽・ISO日付セル | 照合に採用せず、要確認 |
| 台帳キーまたは抽出キーの重複 | 先頭行を採用せず、要確認 |
| 台帳にない抽出キー・抽出結果にない台帳キー | 要確認。不要な台帳行も理由付き除外が必要 |
| 一意に一致し、条件値だけが異なる | 対象外 |
| 確認済みの描画根拠がない・回転ページ | 要確認。自動描画しない |

Excelの日付などが通常の数値セルとして保存されている場合は、その保存数値を扱います。表示書式の解釈はしません。文字列の見出しがある列を選択でき、同名の見出しは列番号で区別します。上限は.xlsx 32MiB、展開サイズ256MiB、データ10万行です。.xls/.xlsm、複数条件、曖昧検索、既存Excelへの追記は対象外です。

## 保存・再開

照合は案件内の `exports/ledger-markups/<照合ID>/` に保存します。

- `ledger.xlsx`：照合に使用した台帳の固定コピー。
- `session.json`：確定結果ID・ハッシュ、条件、判断、根拠、除外理由、出力履歴。
- `output_<出力ID>/`：新規出力したXDW、report.json、SDKログ。

「保存した照合を再開」で、session.jsonのあるフォルダーを選びます。元台帳、固定台帳コピー、確定結果、保存した判断の一致を検証します。元台帳を変更・移動した場合は、現在の台帳を選択して新しく照合してください。案件や試用フォルダーを移動した場合も、台帳の所在が変われば新規照合が必要です。

出力開始時と完了直前に、確定結果・台帳・固定原本のハッシュを確認します。検証後に変わった入力を含む出力は完成扱いにしません。出力先のINCOMPLETE.txtは処理中の印です。残っているフォルダーを完成品として利用しないでください。キャンセル・通常の失敗では今回の一時コピーを破棄し、保存済みの照合を保持します。PC停止などで途中のフォルダーが残った場合は、新規出力へ再試行してください。

出力は毎回固定原本から新しく作ります。出力済みXDWへ重ねて描画せず、既存の出力先を上書きしません。同じ原本ページ・同じmm範囲に複数記録が対応する場合は、枠を1つにして対応IDをまとめます。SDKの矩形は最小3mmなので、小さな根拠は枠だけ拡げ、正確な原本範囲を注釈属性とレポートに保持します。

report.jsonには台帳・シート・条件・確定結果・対象・原本ハッシュ・ページ・元の範囲・理由・除外理由・出力ハッシュを保存します。注釈の `DW_Workbench_LedgerMarkup_v1` 属性にも原本ID／ハッシュ、実ページ、原本mm範囲、記録／項目／確定結果IDを保存します。Excelの行番号は診断表示専用です。キャンバス座標や行番号を描画根拠にしません。

## 合成サンプルのBAT

今回のローカル作業フォルダーにある「台帳照合の合成サンプルを起動.bat」で独立した `ledger-demo` の案件を開きます。既存PortableのPythonを借りて追加版のソースを起動し、案件・設定はledger-demoへ保存します。起動中の既存Workbenchと別の保存先です。

部品番号は000001～000004、描画項目は温度、台帳の「判定」が文字列「対象」と一致するものを赤枠にする例です。000003は重複、999999は抽出結果なし、数式キーも含めています。保存済みの照合では、この例の要確認5件に合成試験用の除外理由を付けています。元の理由・除外内容を画面で確認してください。サンプルの最初の描画範囲は、人が変更した87,32,24,7mmです。テンプレートの85,30,25,8mmより確定した人の根拠を優先します。

BATに `--check` を付けると、実行環境と保存先を確認して終了します。このBATは今回のソースと既存候補runtimeを利用する試用用です。更新済みPortable一式の配布物ではありません。

## 検証と次の公開前確認

DocuWorks 10.1.1の実SDKで合成2文書・4ページを使い、既存の文字・矩形・付箋・子注釈を保持して対象2箇所を追加し、保存・再読込と原本ハッシュ不変を検証しています。追加版の通常起動経路でTk画面を起動し、原文切り抜き・保存再開・二重クリックの抑止・SDK出力も確認しました。

Viewerでの手動目視、実帳票、DocuWorks 9.1、更新済みPortable一式の移動は未確認です。SDK再読込の成功をViewer目視の成功とは扱いません。今回はpush、PR公開、merge、Release、外部送信を行っていません。公開前には開発側で変更をレビューし、Viewer／実環境とPortableの集約チェックを済ませ、開発側と公開側のアカウント・リポジトリを明確にして公開してください。
