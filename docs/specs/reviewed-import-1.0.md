# Canonical → Reviewed 取り込み仕様書

文書版：1.0 ／ 確定日：2026-09-19 ／ 状態：方針確定・実装適合確認前

本書は、本会話で採用された取り込み規則を定める。文書版1.0は保存形式のSchema版とは別であり、既存実装が本書を満たしていることを示さない。

## 1. 目的・対象

Viewerで編集・保存した確認用XDWから、1文書単位で独立したReviewed Resultを作成する。CanonicalはOCRの原記録として不変とし、Reviewedには編集後の最終状態を保存する。編集操作履歴は保存しない。

入力は対応するReview Sessionと保存済みXDW。利用者はViewerで保存して閉じてから取り込む。未保存の編集は対象外とする。原本XDW、Canonical、Sessionの固定ファイル、入力XDW、過去のReviewedは取り込み処理で変更しない。

本書の運用はID照合中心とする。ページの追加・削除・並べ替え・寸法変更・ページ回転は対象外とし、自動検出を保証しない。Structured Result、テンプレート、Excel、原本へのマーカー、レイアウト解析は後続機能とする。

## 2. 文書の識別と検証範囲

新しいIDを重複追加せず、既存の識別情報を次の意味で使用する。

| 識別対象 | 使用する情報 | 意味 |
|---|---|---|
| Review Session | `review_id` | 会話上のSession ID |
| 原本文書 | `identity.json`の`source_sha256` | 原本ファイルの内容識別。独立した業務上の文書番号ではない |
| Canonical | `run_id`と`canonical_manifest_sha256` | OCR実行結果と、その固定保存内容の識別 |
| 編集XDWとSessionの結び付け | XDW文書属性の`review_id`と`identity_sha256` | 上記識別情報を含む`identity.json`への参照 |

取り込み時は、Sessionの形式・固定ファイルの整合性を確認し、XDW文書属性がSession側の期待値と一致することを確認する。これにより、Session・原本・Canonicalの組み合わせを照合する。ファイル名、フォルダー名、ジョブ内の連番だけで判定しない。XDWに三つの名称のIDを直接追加することは要件としない。

必要な文書識別情報の欠落・破損・不一致、Sessionの破損は文書単位のエラーとし、取り込みを中止する。個々の文字項目のoriginの問題は第4節の診断として扱う。

文字列、文字数、Annotation数、文字位置を編集前との一致条件にしない。ID照合中心のモードでは、現在のページ数・ページID・順序・寸法・回転をSessionとの一致条件にしない。結果には検証モードと「ID照合済み／ページ構造未検証」を保存し、再読込時も同じ検証範囲を適用する。

固定データの破損検知、コピー中の入力変更検知、結果の整合性検証は維持する。編集前後のXDW全体のハッシュ一致は要求しない。識別情報の一致は、ページ構造や編集内容の正しさを保証しない。

## 3. 取り込む文字と配置

| 入力の状態 | 規則 |
|---|---|
| ページ直下の通常テキスト | 色、既存・新規、originの有無を問わず本文として取り込む |
| 付箋と、その内部に属する文字 | 本文から除外する。付箋があるだけでは中止せず、内容は保存済みXDWの固定コピーに残す |
| 付箋と見た目だけ重なったページ直下の通常テキスト | 本文として取り込む。見た目の重なりや色では除外しない |
| 付箋以外のグループ等に入れ子になった通常テキスト | 未対応構造として文書全体の取り込みを中止する。黙って省略しない |
| その他の非テキスト | 本文には取り込まない。子孫の判定では付箋の部分木を除外し、それ以外のテキストの有無を確認する |
| 空文字・空白だけの通常テキスト | 項目と元の文字列を保持し、空文字等の診断を付ける。削除扱いにしない |
| 本文0件のページ・文書 | 正常な最終状態として許容する。文字のないページも保存する |

文字列はSDKから取得した保存済みの値を保持し、前後空白、改行、全角・半角、単位表記等を勝手に正規化しない。SDKの読取失敗を空文字・文字0件へ置き換えない。

編集後の配置は、ページ左上原点、右向き+x、下向き+y、単位mmで保存する。ページ番号は取り込みXDWの1始まりとする。文字の外接矩形、回転角（SDKの0～359度）、書字方向（0=横書き、1=縦書き）を取得値から記録する。原本のCanonical座標は変更しない。

現在の全ページを列挙し、各ページの実測情報と本文を保存する。Sessionのページ配列との短い側への切り詰めや、Sessionのページ情報による無条件の置き換えを禁止する。原本領域・原本ページへの対応はoriginから独立して解決する。これはページ構造変更の正式対応を意味しない。

取得順は各ページで1始まりの順序として保存するが、文章の読み順や表の行順とはみなさない。`item_id`は結果内で一意とし、後続処理は`result_id + item_id`で参照する。再取り込み間の項目の同一性は保証しない。

## 4. 複数originと診断

`origins`は、その項目が参照するCanonical領域の集合を表す。空・単一・複数を許容し、同じCanonical領域を複数のReviewed項目が参照してよい。参照が整合することは、編集後の文字内容や人の意図が正しいことの保証ではない。

| 状態 | 保存・利用規則 |
|---|---|
| 属性なし、または明示的な参照なし | `origins=[]`として本文を保持する。正常な状態とし、原本位置は不明とする |
| 有効な参照 | Sessionが識別するCanonicalの領域参照として保持する |
| 存在しない領域・不正な形式 | 本文と参照の診断・取得できた元情報を保持する。不正な参照は原本位置の取得に使わない |
| 別Session・別Canonicalに属する参照 | 本文を保持して異なる由来として診断する。この取り込みでは有効な原本参照として使わない |
| 有効・不正が混在 | 有効な参照を失わず保持し、一部不正であることを記録する。有効部分を参照全体が確定した状態と同一視しない |

参照なしと参照破損を区別する。不正な情報を診断なしで正常な空参照へ変換しない。参照の診断だけを理由に本文を捨てたり、文書全体を拒否したりしない。参照の共有だけを不正としない。

参照の存在・所属はSessionが保持するCanonicalの領域対応情報に照らして確認する。取り込み時に外部Canonicalの再読込を必須としない。後続処理で原本座標を取得するときは、読み込むCanonicalの識別と領域の存在を改めて確認する。

文字修正・移動時は保存されている既存参照を引き継ぐ。新規文字や属性を失った項目には、文字列・位置から参照を推定して付けない。分割後に同じ参照を共有することを許し、結合時の複数参照は明示的に設定する。

初回実装には、対象項目へ複数参照を明示設定し、検証・保存・再読込できる最小のAPIまたは補助操作を含める。設定する領域は対応するCanonicalに限定する。この操作は編集用XDWを対象とし、Canonical、Sessionの固定ファイル、完成済みReviewedを書き換えない。専用GUI、Viewer操作履歴の追跡、参照の自動統合は対象外とする。

## 5. 結果の保存と再取り込み

取り込みごとに新しい`result_id`と新しい結果フォルダーを作る。同じ入力の再取り込みでも別結果とし、以前の結果へ差分追加しない。削除された文字をCanonicalや過去のReviewedから補完しない。

結果には、正本のReviewed JSON、その正本から生成するJSONL、取り込みに用いた保存済みXDWの固定コピー、照合に用いたSession・identity情報、整合性確認用のmanifestを保存する。JSONLは派生物とし、再読込時に正本との一致を検査する。本文0件の場合、JSONにはページ情報を残し、JSONLには本文行を作らない。

文書全体の出力を一時領域で作成・検証した後、一括で完成結果として確定する。SDK読取、ファイル入出力、保存・再読込の失敗、処理中の入力変更、未対応構造では完成扱いにしない。失敗ログ等は完成結果と区別する。既存結果を上書き・自動削除せず、保存期間の管理は本仕様の対象外とする。

利用者には、成功／失敗、本文項目数、除外した付箋数、参照なし項目数、不正な参照を持つ項目数、検証範囲、成功時の保存先を示す。参照なしを異常件数へ混ぜない。

## 6. 互換性と実装境界

複数originと検証モードを持つ新形式は、既存の保存形式1.0と版を分ける。新しいSchema・属性形式・読込規則をセットで定義し、既存のファイルやmanifestを自動更新しない。

旧形式の単一originは、有効なら1件、参照なしなら0件として解釈できるようにする。不正・異なる由来の診断と元情報は保持する。旧形式で参照共有を示す`duplicate`は、新規取り込みで参照を共有すること自体の禁止理由にしない。旧ファイルの読込検証はその旧形式の契約で行う。

従来の厳格なページ検証経路と0.7系の既存APIを維持し、新しいID照合中心の経路を明示して選択する。取り込み時だけ検証を緩め、結果の保存・再読込で旧条件を再適用する実装は禁止する。Schema・Session・XDW属性・manifestの各版の対応を実装設計に記載する。

利用者向けのOCR開始と校正結果取り込みの入口は分け、取り込みの確定処理は1文書単位とする。具体的なAPI名、画面、診断コード名、新Schemaの版番号は、上記規則を満たす実装設計で定める。

## 7. 受け入れ条件

以下は実装の合格条件であり、試験済みという記録ではない。

| 番号 | 確認するケース | 合格条件 |
|---|---|---|
| A01 | 正しいSession／欠落・不一致の文書識別情報 | 一致時は成功。不正時は文書単位で中止し、理由を示す |
| A02 | 文字の修正・追加・移動・削除と再取り込み | 現在の本文を保存し、削除文字が復活せず、新しい結果になる |
| A03 | 複数参照の明示設定、保存、再読込 | 設定した参照集合を維持し、自動推定で参照を追加しない |
| A04 | 同じ元領域を複数項目が参照／参照なし | 全項目を保持し、共有・空参照を不正扱いしない |
| A05 | 参照不正・異なる由来・一部不正 | 本文、有効部分、診断・元情報を保持し、不正部分を原本位置取得に使わない |
| A06 | 付箋メモと、付箋に見た目だけ重なる通常テキスト | 所属で判定し、付箋内だけを除外。XDWコピーにはメモが残る |
| A07 | 付箋以外の未対応構造内のテキスト | 文書単位で中止し、本文を黙って落とさない |
| A08 | 空文字・空白のみ・全本文削除・文字のないページ | 空文字等は保持＋診断、本文0件は成功。ページが残る |
| A09 | Unicode・改行・空白・移動・回転・縦書き | 文字列と編集後の実測配置を保存し、原本座標を変えない |
| A10 | ID照合中心の取り込みと結果の再読込 | 検証範囲が維持され、Sessionとのページ配列処理による欠落・置換がない。対象外のページ変更を合格済みとは報告しない |
| A11 | 旧形式の読込と従来の厳格検証 | 旧形式をその契約で読め、厳格検証経路を維持できる |
| A12 | SDK失敗、入力変更、保存失敗、結果の破損 | 不完全な結果を完成扱いにせず、既存入力・結果を守り、再読込で破損を検知する |

自動試験、実SDKでの保存・再読込、Viewerでの操作確認、現地実文書での運用確認を分けて記録する。架空文書での合格を実文書での確認済みとは扱わない。
