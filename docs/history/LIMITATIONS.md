# 既知制約と不具合

- Windows x64が実運用対象です。wheelの `py3-none-any` は32-bitや他OSでのDocuWorks動作を保証しません。
- OCRはGPU:0必須、PP-OCRv6 mediumの指定構成です。CPU fallback、再開・並列処理、向き分類・傾き補正・文書unwarpは提供していません。複数文書は0.5.0の逐次バッチで処理します。
- 0.4.0では正常推論の0領域ページを保存します。エラーや中断ではerror.jsonと診断を残し、完成manifestや注釈を作りません。診断ディレクトリもローカル扱いです。
- bundleは実文書・認識文字列・画像・元パス・実行環境を含みます。JSONLにも文書内容が含まれます。公開用サンプルに転用せず、外部共有は別途内容確認が必要です。
- SHA-256は整合性検査であり署名ではありません。JSON Schemaだけでは座標・ID・ファイルhashの整合性を保証しません。
- Markerは領域の外接矩形に基づく水平線です。斜め文字に沿う四角形やOCR文字列そのものの編集ではありません。線幅は領域高さから整数ptに丸め、最低1ptです。
- Coreは明示的 `save()` が必要です。作成途中の属性設定失敗は同じハンドル内に部分変更を残し得ます。失敗後は保存せず閉じ、新しいコピーでやり直してください。
- Coreの別wrapperのキャッシュは削除と同期しません。削除後の古い参照を使わず、再列挙してください。0-byte User属性GETにも制約があります。
- **Core 1.0.0 / Python 3.10:** with本体例外とclose失敗が重なると `exc.add_note()` により元例外がAttributeErrorで隠れます。未修正です。3.11以降を用い、3.10ではclose失敗を別記録して元例外を再送出する処理が必要です。
- Coreの既存テスト1件はインストール済みDLLとcompanionのパッチ版が異なることまで要求します。他PCでの失敗はライブラリ不具合と即断できません。
- Integrationsの旧実機テストはSystem32 DLLを直接指定します。別配置の製品環境ではその試験をそのまま汎用の合格条件にしないでください。
- 過去のViewer成功報告は継承記録です。0.4.0では複数ページGPU OCR・実文書保存を追加検証しましたが、Viewer操作は未確認です。
- モデル配信URL・依存パッケージの将来の可用性は保証しません。GPU lockはPaddle wheel以外が版固定のみです。
