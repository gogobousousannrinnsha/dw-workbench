# テンプレートからCSVまで

DW-OCR v0.6.1 Pre-release / Integrations 0.12.0向けの手順です。
コマンドは実装済みです。Viewerの手操作による一連の確認は未実施です。
公開済みv0.4.1では利用できません。確認範囲は[配布構成と検証方針](../maintainer/RELEASE_v0.6.1.md)と、Releaseに添付する最終検証報告を参照してください。

テンプレートの準備には[テンプレート作成画面](template-editor.md)を使えます。画面で登録済みの場合は手順2・3を省き、手順4のテンプレートパスを実際の登録先（例：`templates\帳簿A\v001`）へ置き換えてください。手順2・3は従来の手動設定・CLI登録の方法です。

## 1. 校正後の結果を用意する

[標準操作](README.md)に従い、OCR、Viewerでの修正・保存、校正結果取込を行います。
取り込み画面のReviewed保存先を控えてください。テンプレートの適用対象は、この結果に保存された文字と位置です。
校正し直した場合は再取り込みし、利用する結果を自分で選びます。

## 2. 1つのXDWに複数の矩形を置く

同じ帳票の校正済みreview.xdwを別名でコピーし、例として「帳簿A.xdw」を作ります。
元のreview.xdw、initial.xdw、登録済みのファイルは変更しません。
コピー上の文字を目印に、取得したい値を四角形アノテーションで囲みます。
ページに直接置き、付箋やグループの中には入れないでください。
文字枠の中心が範囲内にある文字項目を丸ごと取得します。文字項目の一部分だけを切り出す指定はできません。

矩形の［プロパティ］→［ユーザー定義］へ、次の例の属性を設定します。

| 属性名 | 種類 | 部品番号の矩形 | 温度の矩形 | 帳票名の判定用矩形 |
| --- | --- | --- | --- | --- |
| 用途 | 文字列 | 取得 | 取得 | 適用判定 |
| 項目名 | 文字列 | 部品番号 | 温度 | 帳票名 |
| 期待文字 | 文字列 | 設定しない | 設定しない | 帳簿A |
| 必須 | 有無 | 有 | 有 | 設定しない |
| 出力順 | 整数 | 1 | 2 | 設定しない |
| 結合方法 | 文字列 | 連結 | 連結 | 設定しない |

判定用矩形は、毎回同じ位置にある帳票名などを囲みます。上の例では「帳簿A」と一致することを条件にします。
複数の判定用矩形を置く場合は全条件の一致が必要です。判定用矩形を省略するとページ情報だけの判定になります。
同じ用途の項目名は重複させません。入力し終えたらXDWを保存してViewerを閉じます。
詳しい属性・取得規則は[矩形テンプレート仕様](../RECTANGLE_TEMPLATE.md)を参照してください。

## 3. テンプレートを登録・確認する

以下は新しいPortableのフォルダーを作業場所にしたPowerShellの例です。
出力先の親フォルダー「templates」「structured」「exports」を先に作ります。
「帳簿A.xdw」もこの作業場所に置きます。各コマンドを1つずつ実行して表示を確認してください。

```powershell
.\docuworks-integrations.bat register-template --template-xdw "帳簿A.xdw" --name "帳簿A" --output-dir "templates\帳簿A-001"
.\docuworks-integrations.bat check-template --template-dir "templates\帳簿A-001"
```

登録にはDocuWorksが必要です。登録後の確認・適用とCSV出力にはSDKやGPUを使いません。
登録先にはXDWの固定コピー、定義、確認用情報を保存します。登録済みJSONを手で編集しないでください。
矩形・項目名・条件を変えるときは、作成用XDWを修正して「帳簿A-002」など新しいフォルダーへ登録します。

## 4. 文書ごとに項目を取得する

`テンプレート適用.bat`を開き、校正結果と登録版を選びます。[選択画面から適用する手順](template-apply.md)を参照してください。引数や保存先を指定する場合は、従来どおり以下のコマンドも使えます。

次の「OUTPUT\job-例\doc-000001\reviewed\result-例」は実在するReviewedの保存先へ置き換えます。
check-templateは保存せずに確認し、apply-templateが新しいStructured Resultを保存します。

```powershell
.\docuworks-integrations.bat check-template --template-dir "templates\帳簿A-001" --reviewed-dir "OUTPUT\job-例\doc-000001\reviewed\result-例"
.\docuworks-integrations.bat apply-template --template-dir "templates\帳簿A-001" --reviewed-dir "OUTPUT\job-例\doc-000001\reviewed\result-例" --output-dir "structured\帳簿001"
```

2文書目も同じ登録テンプレートで実行し、別の出力先「structured\帳簿002」へ保存します。
状態は次のとおりです。適用不可や要確認でも診断付きの結果が保存されます。

| 表示 | 内容と次の操作 |
| --- | --- |
| 取得完了 | 項目の値を確認する。取得完了でも確認事項があれば読む |
| 要確認 | 必須項目の欠落、回転・縦書きなどを確認する。必要なら再校正・再取り込み・再取得する |
| 適用不可 | ページ情報や期待文字の不一致を確認し、正しい帳票・テンプレートを選ぶ |
| 処理できませんでした | 入力・保存先などを直す。完成結果は作られない |

位置補正・拡大縮小・自動テンプレート選択は行いません。校正で文字を動かした場合は、移動後の位置へ範囲を合わせます。

## 5. CSVへまとめる

同じ登録テンプレートを使ったStructured Resultを選び、文書名と対で指定します。
「帳簿001.xdw」などは一覧に表示する名前です。入力順がCSVの行順になります。

```powershell
.\docuworks-integrations.bat export-structured-csv --entry "structured\帳簿001" "帳簿001.xdw" --entry "structured\帳簿002" "帳簿002.xdw" --output "exports\帳簿A.csv"
```

列は「文書名、処理結果、部品番号、温度、確認事項、結果ID」のように並びます。
取得項目はテンプレートの出力順です。適用不可の文書も行として残ります。
再登録した別版のテンプレートを使った結果は別CSVにしてください。
既存CSVへの追記・上書きはしません。出し直すときは新しいファイル名を指定します。

各コマンドの終了コードは0が正常、2が要確認または適用不可、1が処理失敗です。
apply-templateとCSV出力では、コード2でも診断を含む完成結果が保存されています。
結果フォルダーの自動探索や最新版の自動選択はありません。

## 6. Excelで確認し、結果を保管する

CSVはUTF-8（BOM付き）です。Excelの［データ］→［テキスト/CSVから］で取り込み、
取得値の列を文字列として扱ってから読み込みます。直接開くと先頭ゼロや日付に見える値が変換される場合があります。
セルの型を持つ.xlsx出力は今回の対象外です。詳しくは[CSV仕様](../STRUCTURED_CSV.md)を参照してください。

正本はStructured Resultのstructured.jsonです。CSVを編集しても正本は変わりません。
結果IDとStructured Resultのフォルダーを一緒に保持すると、取得元や確認事項を後から調べられます。
原本、runs、Review Session、Reviewed、登録テンプレートも保管します。
これらには文書内容や作業用XDWが含まれるため、配布用ファイルには含めません。
